### 📌 Цель работы
Сформировать умения, необходимые для работы с файлами, потоками ввода-вывода, предопределенными потоками, а также реализовать механизм сериализации и десериализации объектов иерархии классов с восстановлением их типов.

### 📂 Задания и реализация

#### Задание 1: Текстовая сериализация с паттерном Factory
- **Условие:** Разработать подсистему хранения для системы "Зоопарк" (продолжение Lab 3). Реализовать сохранение и загрузку разнородных объектов в текстовый файл с использованием тегов типов.
- **Код:** [lab4task1](./lab4task1.cpp)
- **Ключевые особенности:**
  - **Паттерн Factory:** Класс `AnimalFactory` со статическим методом `create()`, который по строковому тегу (`"LION"`, `"ELEPHANT"`, `"PENGUIN"`, `"DOLPHIN"`) создает объект нужного класса
  - **Виртуальные методы `save()` и `load()`:** Каждый подкласс переопределяет их для записи/чтения своих специфических атрибутов, вызывая сначала методы базового класса (`Animal::save(out)`)
  - **Обработка исключений:** Класс `DataStorage` выбрасывает `std::runtime_error` при ошибках открытия файла, записи или чтения
  - **Демонстрация устойчивости:** Обработка случаев несуществующего файла и поврежденных данных

#### Задание 2: Бинарная сериализация с произвольным доступом
- **Условие:** Реализовать класс `BinaryStorage` для записи и чтения объектов в произвольную позицию бинарного файла с проверкой целостности данных через контрольную сумму.
- **Код:** [lab4task2](./lab4task2.cpp)
- **Ключевые особенности:**
  - **Произвольный доступ:** Использование `seekp()` и `seekg()` для перемещения указателя записи/чтения в любую позицию файла
  - **Контрольные суммы (Checksum):** Функция `calculateChecksum()` вычисляет сумму байт данных для проверки целостности при чтении
  - **Бинарная сериализация строк:** Вспомогательные функции `writeString()` и `readString()` сначала записывают/читают длину строки (8 байт), затем сами символы
  - **RAII через `std::unique_ptr`:** Владение файловым потоком через умный указатель (`unique_ptr<fstream>`) гарантирует корректное закрытие файла
  - **Обработка граничных случаев:** Проверка выхода позиции за границы файла, повреждение данных на байтовом уровне

#### Задание 3: Сериализация иерархии классов с восстановлением типов
- **Условие:** Реализовать механизм сохранения и загрузки вектора разнородных объектов (`std::vector<std::unique_ptr<Animal>>`) с полным восстановлением их типов и вызовом специфических методов после загрузки.
- **Код:** [lab4task3](./lab4task3.cpp)
- **Ключевые особенности:**
  - **Использование `std::unique_ptr`:** Полный отказ от сырых указателей в пользу умных (эволюция от Lab 3)
  - **Полиморфная сериализация:** Метод `getType()` возвращает строковый идентификатор класса, который используется Factory при десериализации
  - **Восстановление типов:** После загрузки из файла объекты корректно восстанавливают свой тип, что доказывается вызовом специфического метода `getSpecificFeature()` для каждого подкласса
  - **Класс `HierarchyStorage`:** Инкапсулирует логику сохранения/загрузки коллекции, используя `std::move()` для эффективной передачи владения объектами

### 🎯 Что было изучено и реализовано:

**Работа с файлами и потоками:**
- ✅ **Текстовые потоки:** `std::ofstream`, `std::ifstream` для работы с человекочитаемыми данными
- ✅ **Бинарные потоки:** `std::fstream` в режиме `ios::binary` для эффективного хранения
- ✅ **Произвольный доступ:** Методы `seekp()`, `seekg()`, `tellg()` для навигации по файлу

**Сериализация и десериализация:**
- ✅ **Паттерн Factory:** Создание объектов по строковому идентификатору типа
- ✅ **Виртуальные методы `save()`/`load()`:** Полиморфная запись/чтение атрибутов
- ✅ **Контрольные суммы:** Проверка целостности данных через вычисление checksum
- ✅ **Бинарная сериализация строк:** Запись длины строки перед её содержимым

**Управление памятью и ресурсами:**
- ✅ **`std::unique_ptr`:** Владение объектами и файловыми потоками (RAII)
- ✅ **`std::vector<std::unique_ptr<Animal>>`:** Хранение полиморфной коллекции
- ✅ **`std::move()`:** Эффективная передача владения умными указателями

**Обработка ошибок:**
- ✅ **Исключения:** `std::runtime_error`, `std::out_of_range` для сигнализации об ошибках
- ✅ **Проверка состояния потоков:** Методы `fail()`, `is_open()` для контроля операций ввода-вывода
- ✅ **Блоки `try-catch`:** Демонстрация обработки различных сценариев ошибок

### 💡 Выводы и инсайты

В ходе выполнения лабораторной работы:

1. **Понял разницу между текстовой и бинарной сериализацией:**
   - Текстовый формат удобен для отладки и человекочитаем, но занимает больше места
   - Бинарный формат эффективнее, но требует точного знания структуры данных

2. **Оценил мощь паттерна Factory:**
   - Без него десериализация разнородных объектов была бы невозможна
   - Factory позволяет добавлять новые классы (например, `Tiger`) без изменения кода загрузки

3. **Освоил произвольный доступ к файлам:**
   - Методы `seekp()`/`seekg()` работают как "закладки" в книге — можно прыгнуть на любую страницу
   - Это критически важно для больших файлов, где чтение всего содержимого неэффективно

4. **Понял важность контрольных сумм:**
   - Реальная демонстрация повреждения файла показала, как checksum ловит ошибки
   - Это основа надежности систем хранения данных

5. **Перешел на Modern C++:**
   - Использование `std::unique_ptr` вместо сырых указателей消除了 риск утечек памяти
   - RAII гарантирует, что файлы закроются даже при выбросе исключения
